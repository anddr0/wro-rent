# Правила репозитория

Telegram-бот и мини-апп для проката велосипедов. Устройство проекта и команды —
в `README.md`, принятые решения — в `docs/decisions.md`.

## Главное правило кода: качественно, но просто

Код должен понимать человек, который видит проект впервые.

- Явное лучше короткого. `if/else` вместо вложенных тернарников,
  обычный цикл вместо цепочки `reduce`/`flatMap`, если так понятнее.
- Синтаксический сахар — только там, где он делает код _понятнее_, а не короче.
  Нормально: `?.`, `??` для простых значений по умолчанию, деструктуризация пропсов.
  Избегаем: `??=`, `||=`, вложенные тернарники, хитрые однострочники,
  неочевидные регулярки (если без неё никак — комментарий, что она делает).
- Понятные имена вместо комментариев. Комментарий объясняет _зачем_, а не _что_.
- Маленькие функции с одной задачей. Не плодим абстракции «на будущее».
- TypeScript в strict-режиме, без `any`. Типы базы — из `@/lib/database.types`.
- Код, имена и комментарии на английском; тексты для пользователей — на русском.

## Где какой код

Одно Next.js-приложение, всё в `src/`:

- `src/app` — только роутинг: страницы, layout-ы, API-роуты. Логика — не здесь.
- `src/bot` — логика бота (команды, ответы); получает зависимости параметрами.
- `src/server` — код только для сервера (`import "server-only"`):
  секреты, Supabase, проверка Telegram initData.
- `src/lib` — код для браузера и общий: хуки, типы.
- `src/lib/database.types.ts` — сгенерирован, руками не правим (`npm run db:types`).
- `src/components` — UI-компоненты.

## База данных

- Схема меняется только миграциями (`supabase/migrations`), не через дашборд.
- Применённую где-либо миграцию не редактируем — пишем новую.
- После изменения схемы: `npm run db:reset` → `npm run db:types` → `npm run typecheck`.
- Браузер в Supabase не ходит: доступ только через сервер с секретным ключом,
  права проверяет сервер (`requireUser` / `requireAdmin`).

## Перед коммитом

`npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build` должны проходить.
Форматирование не обсуждаем и не правим руками: это делает Prettier (`npm run format`).

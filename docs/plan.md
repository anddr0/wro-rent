# План реализации

Как дойти от того, что есть, до запуска MVP. Что именно делаем — в
[user-stories.md](user-stories.md), здесь — в каком порядке.

- **Блок** — большая часть продукта (каталог, бронирование, админка броней…).
- **Срез** — кусок, который можно потрогать в Telegram: проходит насквозь
  от базы до экрана. Один срез — один или несколько коммитов.
- **Шаги** — из чего состоит срез, обычно в таком порядке: миграция → сервер → API → экран → бот → проверка.

Правила:

- Миграцию пишем в том срезе, где она нужна, а не все заранее.
- Срез готов, когда проверен в Telegram и проходят все проверки перед коммитом.
- После блока 0 каждый готовый срез выкатываем на прод: проблемы видны сразу, а не перед запуском.
- Порядок блоков — по пути клиента: увидел велосипед → оставил заявку → админ подтвердил → клиент узнал.

## Уже сделано

- Бот на вебхуке, команда `/start` с кнопкой мини-аппа.
- Схема базы: пользователи, велосипеды, тарифы, брони.
- Авторизация: проверка initData, `requireUser` / `requireAdmin`, `/api/me`, тесты.
- Главный экран: приветствие, аватар, роль.

## Блок 0. Фундамент

### 0.1. Первый деплой

Пустое приложение на проде, чтобы дальше выкатывать каждый срез.

- [ ] облачный Supabase: `link` + `db push` миграций (seed на прод не идёт);
- [ ] проект на Vercel, переменные окружения;
- [ ] прод-бот в BotFather, вебхук на прод-домен, кнопка меню с мини-аппом;
- [ ] первый админ — SQL-запросом в облачной базе;
- [ ] проверка: прод-бот → мини-апп → «Привет, …» с ролью.

### 0.2. Каркас мини-аппа

- [ ] страницы: каталог, велосипед, мои брони, админка (`/admin/...`);
- [ ] навигация: вкладки для клиента, у админа — ещё вход в админку;
- [ ] текущий пользователь доступен на всех страницах (один запрос `/api/me` на старте);
- [ ] кнопка «Назад» Telegram на внутренних страницах;
- [ ] сервер не пускает в `/api/admin/...` без `requireAdmin` — проверка curl-ом.

### 0.3. Языки (В-1)

Делаем рано: тогда каждый экран сразу пишется с переводами, а не переделывается потом.

- [ ] выбрать подход к переводам (библиотека или свой словарь) — записать в decisions;
- [ ] миграция: `users.locale`;
- [ ] язык по умолчанию: из Telegram, если поддерживаем, иначе польский;
- [ ] переключатель языка, выбор сохраняется;
- [ ] пока тексты на русском и польском, английский и украинский — перед запуском;
- [ ] обновить правило в CLAUDE.md «тексты для пользователей — на русском».

## Блок 2. Заявка на бронь

### 2.1. Брони в базе

- [ ] миграция: статус `rejected`, пересечение запрещено только для `confirmed` и `active`;
- [ ] окончание брони = начало + длительность тарифа (часовой пояс — Варшава) + тесты.

### 2.2. Выбор даты и времени (К-3)

- [ ] `GET /api/bikes/[id]/availability`: занятое время и время с заявками в ожидании;
- [ ] выбор даты и времени начала: пересечение с занятым не выбрать,
      плашка «Кто-то уже ждёт подтверждения».

### 2.3. Отправка заявки (К-4, К-5)

- [ ] `POST /api/bookings`: проверки (велосипед виден, тариф активен, даты свободны), цена из тарифа;
- [ ] экран заявки: тариф, дата и время начала, комментарий;
- [ ] экран «Заявка отправлена».

### 2.4. Телефон (К-9)

- [ ] кнопка «Поделиться контактом» в мини-аппе;
- [ ] бот получает контакт и сохраняет `users.phone`;
- [ ] без username заявку не отправить, пока нет телефона.

### 2.5. Уведомление админам (А-8)

- [ ] отправка сообщений ботом из сервера (общая функция, язык получателя);
- [ ] сообщение всем админам о новой заявке, кнопка «Открыть»
      (до среза 4.2 ведёт просто в мини-апп).

## Блок 4. Админ: брони

### 4.1. Список броней (А-6)

- [ ] `GET /api/admin/bookings`: фильтр по статусу и датам, новые сверху;
- [ ] экран списка с фильтрами.

### 4.2. Карточка брони (А-7, просмотр)

- [ ] `GET /api/admin/bookings/[id]`;
- [ ] экран: клиент, велосипед, тариф, даты, цена, статус, комментарий, кнопка «Написать»;
- [ ] кнопка «Открыть» из уведомления (2.5) ведёт сюда.

### 4.3. Подтвердить или отклонить (А-7, К-8)

- [ ] подтверждение и автоотклонение пересекающихся заявок — одной транзакцией в базе;
- [ ] отклонение;
- [ ] клиентам уходят сообщения: подтверждена / отклонена / даты уже заняли.

### 4.4. Выдача, возврат, отмена (А-7, К-8)

- [ ] отметить выдачу и возврат;
- [ ] отменить подтверждённую бронь, клиенту — сообщение.

### 4.5. Цена, оплата, заметка (А-7, К-8)

- [ ] изменить цену, клиенту — сообщение;
- [ ] депозит, способ и время оплаты;
- [ ] заметка админа.

- [ ] переводы на английский и украинский, заказчик вычитывает все тексты;

- [ ] прод-бот: имя, описание, аватар, команды;

## После запуска

- А-12 — удаление тарифа, А-13 — бронь вручную;
- фильтры броней по цене, велосипеду, клиенту;
- настройка уведомлений у каждого админа;
- напоминания клиенту о возврате (по расписанию).
